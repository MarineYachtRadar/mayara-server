Raymarine radar setup

RDxxx and RDxxxHD radomes, Quantum and Quantum 2, Cyclone, Magnum and the open arrays.

What you need

  • The radar and the Mayara machine on the same wired Ethernet network
  • A DHCP server on that network — this is the one hard requirement
  • A RayNet-to-RJ45 adapter cable, unless the radar already reaches a switch
DHCP is not optional

A Raymarine radar has no fallback address. It asks for one by DHCP, and until it gets a lease it stays silent — no beacons, nothing for Mayara to find. The DHCP server can be a Raymarine MFD, your router, or a DHCP service on the Mayara machine itself. If the radar is not detected, check your router's lease list first: if the radar is not in it, nothing else you change will help.

Wired (RayNet)

A wired radar needs no pairing, no WiFi credentials, and no extra Mayara options. Connect it to the same network as Mayara, make sure DHCP is available, and it is discovered automatically. An MFD is not required — Mayara wakes and drives the radar itself (Mayara 3.7.0 and later).

If your radar is wired you can skip the pairing section below — but not the WiFi story altogether, because a Quantum is a WiFi radar inside whatever you connect to it. See Quantum networking explained.

Those 232.x.x.x groups sit in a range some managed switches treat differently from ordinary multicast. If the radar is discovered but no picture appears, IGMP snooping on a managed switch is a prime suspect.

WiFi (Quantum)

A Quantum announces itself on two multicast groups: the RayNet one that every Raymarine radar uses, and a second one it uses when its own link to the chartplotter is WiFi. Mayara listens on both, always. A radar whose link to the chartplotter is wireless is still perfectly findable from a Mayara that is wired to RayNet, and needs no extra options.

The flag is only about Mayara's own network interfaces: by default Mayara ignores the wireless interfaces of the machine it runs on, so if the only path to the radar is over your own WiFi adapter you have to allow it. It never connects Mayara to a radar and never asks for credentials — and it has nothing to do with whether the radar is wireless.

Why the WiFi credentials on the label rarely work

They do work — but only for as long as the radar has never been paired with a chartplotter. A brand-new Quantum puts its own network on the air, named after its serial number, and repeats that briefly every ten seconds so an installer can find it. That is the network the label describes.

Pairing turns it around. You type the label's name and passcode into the chartplotter, the chartplotter briefly presents a network by that name, and the radar joins it. The chartplotter then hands the radar the details of every chartplotter's own WiFi on the boat and goes back to its normal network name. From then on the radar is a client: it stops advertising, and at each power-up it joins whichever chartplotter has the strongest signal.

So on an already-installed boat, scanning for the name on the label finds nothing — the radar is not offering a network any more, it is on the chartplotter's. And an unpaired radar gives up and goes to sleep about an hour after power-up, so even a fresh one is only findable for a while.

Mayara, at this time, can work with wireless Quantum radars in the following manners:

  1. Mayara wired to the RayNet network the MFD is on, with the radar also wired. Nothing special is needed.
  2. Mayara wired to RayNet, with the radar reaching the MFD over WiFi. The MFD bridges the radar onto the wired network, and again nothing special is needed on Mayara's side.
  3. Mayara joined to the WiFi network the MFD creates, alongside the radar. This one needs --allow-wifi, because Mayara itself is on a wireless interface.

In all three the MFD has to remain on: it is the MFD that provides the network the radar joined, and it does not hand that job over.

A radar that has never been paired is the interesting case, because there it is the radar offering the network and no chartplotter is involved at all. If you have a wireless Quantum — paired or not — and are willing to experiment, please get in touch. What we will not rush is handing a radar a different network to join: get that wrong and the radar stops talking to the boat's own chartplotter.

Every Quantum is a WiFi radar inside

The part of a Quantum that spins — antenna, transmitter and the processing behind them — reaches the fixed base by 2.4 GHz WiFi. Nothing but power crosses the rotating joint. On a cable-capable model a bridge board in the base joins that internal network and pushes the picture out of the socket, so the cable does not start at the radar: it starts one step after a WiFi link.

That has consequences worth knowing — chiefly that 2.4 GHz congestion can cost you picture quality even on a wired radar, and that a WiFi scan near one may show a network named after it. Quantum networking explained walks through it with diagrams.

Troubleshooting

The picture works but no control does

If the radar paints, the ranges are right and the status updates, but power, gain, sea and range do nothing at all, the radar is almost certainly on a different IP subnet from the machine running Mayara.

This is normal on Raymarine networks and it particularly affects the RD and HD radomes. Those radars address themselves in the 10.x.x.x range, while a chartplotter's DHCP server hands your Mayara machine an address in 198.18.x.x. The two share one cable but not one subnet. The chartplotters cope because they give themselves an address in both ranges; an ordinary computer has only the one it was given.

The radar's picture and status still arrive, because those are multicast and are delivered whatever the addressing. Controls are sent straight to the radar's own address, so they leave by whichever network connection the machine thinks is the way out — never the radar. Mayara logs a warning naming the two addresses when it spots this.

The fix is to give the Mayara machine an address on the radar's subnet as well. Find the radar's address in Mayara's log, then, on Linux: 

# the radar is, say, 10.18.203.88 and your radar network card is eth0
sudo ip addr add 10.0.0.2/8 dev eth0

Pick an address in 10.x.x.x that nothing else is using. Adding a route to the radar alone also works: sudo ip route add 10.18.203.88/32 dev eth0. Either way the change is not permanent — put it in your network configuration so it survives a reboot.

Radar not detected

  • Check the DHCP lease list and confirm the radar actually has an address.
  • Confirm Mayara is on the same network as the radar.
  • On a managed switch, check IGMP snooping against the 232.x.x.x groups above.
  • If Mayara is on WiFi rather than wired, confirm --allow-wifi is set. A radar that is on WiFi does not by itself need the flag.
  • Name the interface if the machine has several: mayara-server -i eth0
  • Run mayara-server -vv and watch for beacons.

Wired Quantum is detected but never wakes

Upgrade to Mayara 3.7.0 or later. Earlier versions did not wake a Quantum and required a Raymarine MFD to be present on the network.

Quantum over WiFi is unreliable

  • Signal strength and interference decide everything here. Move the Mayara machine closer, or switch to wired.
  • Missing spokes are the classic symptom of a marginal WiFi link.
