Raymarine radar setup

Quantum and Quantum 2, Cyclone, the RD radome series, Magnum and the open arrays.

What you need

  • The radar and the Mayara machine on the same wired Ethernet network
  • A DHCP server on that network — this is the one hard requirement
  • A RayNet-to-RJ45 adapter cable, unless the radar already reaches a switch
DHCP is not optional

A Raymarine radar has no fallback address. It asks for one by DHCP, and until it gets a lease it stays silent — no beacons, nothing for Mayara to find. The DHCP server can be a Raymarine MFD, your router, or a DHCP service on the Mayara machine itself. If the radar is not detected, check your router's lease list first: if the radar is not in it, nothing else you change will help.

Wired (RayNet)

A wired radar needs no pairing, no WiFi credentials, and no extra Mayara options. Connect it to the same network as Mayara, make sure DHCP is available, and it is discovered automatically. An MFD is not required — Mayara wakes and drives the radar itself (Mayara 3.7.0 and later).

If your radar is wired, you can ignore the WiFi section entirely.

Those 232.x.x.x groups sit in a range some managed switches treat differently from ordinary multicast. If the radar is discovered but no picture appears, IGMP snooping on a managed switch is a prime suspect.

WiFi (Quantum)

Some Quantum radars can run over WiFi, and unlike most radars they can actually get away with it: a Quantum sends fewer and coarser spokes than any other radar here, and compresses them on top of that. Expect it to work, but wire it if you can.

Start Mayara with --allow-wifi to use one. The flag governs Mayara's own network interfaces — by default Mayara ignores wireless interfaces on the machine it runs on. It does not connect Mayara to the radar and never asks for credentials.

Why the WiFi credentials on the label rarely work

The network name and password printed on the radar are real: they belong to an access point the radar itself puts up. The catch is when it is there. The radar broadcasts it for a while after power-up so a Raymarine MFD can find it and pair. Once pairing is done the radar switches to being an ordinary client of the MFD's network and stops broadcasting altogether.

So by the time you go looking on a phone or laptop, the network has usually gone — and if you are scanning while the radar is already paired and running, it is never coming back on its own. What you see in the scan instead is whatever else is on the boat, which is why the name on the label seems not to match anything.

Mayara does not yet know how to pair with the radar over its startup network. If we do this, we may accidentally throw the radar off the existing chartplotters, so this will have to wait until a user turns up that has the guts to try it.

Mayara, at this time, can work with wireless Quantum radars in the following manners:

  1. It can be wired to the RayNet network that a Raymarine MFD is on. The MFD will bridge the radar data onto the wired network.
  2. It can be connected to the WiFi network created by a Raymarine MFD. Mayara will talk directly to the radar but needs the WiFi network to remain operational.

In both of these cases the MFD has to remain on and Mayara needs to be started with --allow-wifi. If you are interested in improving this behavior, feel free to get into contact.

Troubleshooting

Radar not detected

  • Check the DHCP lease list and confirm the radar actually has an address.
  • Confirm Mayara is on the same network as the radar.
  • On a managed switch, check IGMP snooping against the 232.x.x.x groups above.
  • For a Quantum on WiFi, confirm --allow-wifi is set.
  • Name the interface if the machine has several: mayara-server -i eth0
  • Run mayara-server -vv and watch for beacons.

Wired Quantum is detected but never wakes

Upgrade to Mayara 3.7.0 or later. Earlier versions did not wake a Quantum and required a Raymarine MFD to be present on the network.

Quantum over WiFi is unreliable

  • Signal strength and interference decide everything here. Move the Mayara machine closer, or switch to wired.
  • Missing spokes are the classic symptom of a marginal WiFi link.
