ONWA radar setup

The ONWA KRA-5001 radar, as used with the K-ASTRAL chartplotters. Mayara can run the radar on its own or alongside the chartplotter.

What you need

  • The radar wired to the same Ethernet switch as the Mayara machine
  • An address for the Mayara machine in 223.168.1.x
  • UDP ports 3823, 7203 and 7204 open on the host firewall

Network requirements

The radar sits at a fixed address, 223.168.1.168, with the chartplotter at 223.168.1.128. It sends its picture and status as broadcasts, which Mayara hears on any address, but it takes its commands by unicast, so the Mayara machine needs an address of its own in 223.168.1.x. Pick one nothing else uses, for example 223.168.1.200 with netmask 255.255.255.0.

On Linux: ip addr add 223.168.1.200/24 dev eth0. On macOS: sudo ifconfig en0 alias 223.168.1.200 255.255.255.0.

WiFi will not work for the radar

The picture arrives as UDP broadcast, about 4 MB/s, which WiFi handles exactly like multicast: base rate, no retransmissions, heavy airtime cost. Wire the radar to Mayara and view Mayara over WiFi. The full explanation.

Traffic

PurposeAddressNotes
Commands 223.168.1.168:3367 Unicast, from Mayara or the chartplotter
Status and discovery 255.255.255.255:3823 Every setting, once a second
Radar picture 255.255.255.255:7203 One spoke per packet
Command replies 255.255.255.255:7204 Echo of every command, versions

Controls

The chartplotter and Mayara control the same radar, so a change made on either shows up on both.

  • Power — standby or transmit
  • Range — 1/8 nm to 36 nm, the chartplotter's range steps
  • Gain, Sea clutter, Rain clutter — 0–100%
  • Interference rejection — off, low, medium, high
  • Target expansion — the chartplotter's echo stretch: off, low, high
  • Noise rejection — off or on
  • Display timing — the chartplotter's sweep timing, 0–100
  • No-transmit sector — the chartplotter's dead sector

Manual tuning is not offered: the K-ASTRAL sends the same value whatever the tune sliders are set to, so the radar's tuning range is not known. The radar tunes itself whenever it starts transmitting.

Troubleshooting

Radar not detected

  • Confirm the Mayara machine has an address in 223.168.1.x.
  • Confirm nothing is blocking UDP port 3823.
  • Limit detection to ONWA to cut down the noise: mayara-server --brand onwa

No spokes displayed

The radar has to be transmitting. It does not report its own warm-up, so Mayara does what the chartplotter does: when it first finds the radar in standby, or the radar has just been switched on, it shows Preparing and counts down 100 seconds before it allows transmit.

The radar only keeps transmitting while something polls it every second; Mayara and the chartplotter both do. If Mayara stops and the chartplotter is off, the radar returns to standby within about ten seconds.
