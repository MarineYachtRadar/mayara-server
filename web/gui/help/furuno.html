Furuno radar setup

DRS4W, DRS, DRS-NXT, X-Class, and FAR commercial series

What you need

  • An address on the 172.31.0.0/16 subnet on the Mayara machine
  • A wired Ethernet connection to the radar (except the DRS4W, which is WiFi)
  • For a FAR-2xx7: IMO mode B, C or W — not mode A
The subnet is mandatory

All Furuno radars live on 172.31.0.0/16. If the machine running Mayara has no address in that range, the radar is never detected — there is no discovery mechanism that works around it. The Interfaces button on Mayara's radar list shows which interfaces Mayara is listening on for each brand.

Recommended configuration

  • Address: 172.31.3.150, or any unused 172.31.x.x
  • Netmask: 255.255.0.0
  • No default gateway — this is a local subnet only
ip addr add 172.31.3.150/16 dev eth1
A wired Furuno belongs on wired Ethernet

A DRS compresses its spokes, so it is not a heavy talker by radar standards — roughly 200 to 400 bytes per spoke. That does not rescue it on WiFi. Spoke data is multicast, and WiFi carries multicast at the base rate with no retransmissions, so what is lost is lost. The full explanation.

The DRS4W below is the exception, and it shows what a WiFi radar actually costs: it sends 16 to 24 bytes per spoke, roughly a fifteenth of what a wired Furuno sends — and about a twenty-fifth per revolution, because it sends fewer spokes as well. Furuno designed it that way from the start.

Make sure the host firewall accepts inbound UDP on ports 10010 and 10024, TCP on 10010 for the login handshake, and UDP on the report/command port the radar hands out during that login — 10100 in every capture we have.

DRS and DRS-NXT series

DRS4D-NXT, DRS6A-NXT, DRS12A-NXT, DRS25A-NXT and the older DRS and X-Class models work as soon as the subnet is right. Nothing has to be changed on the radar itself; it broadcasts discovery beacons and Mayara identifies the model from them.

DRS4W "1st Watch"

The DRS4W is its own access point. Connect the Mayara machine to the radar's WiFi network and start Mayara with --allow-wifi so it does not skip the wireless interface.

In our testing the DRS4W also handed out an IP address by DHCP, so no network settings need to be changed.

Multiple clients are allowed at once, so you can keep using the standard Marine Radar iOS application alongside Mayara.

FAR series (FAR-2xx7, FAR-15x3, FAR-3000)

IMO mode

A FAR-2xx7 must be in IMO mode B, C or W for network access; mode W is the one to pick. In mode A the radar is standalone and ignores the network completely.

  1. Hold the HL OFF button.
  2. While holding it, press MENU five times.
  3. Go to Installation → Type.
  4. Select W (recommended), B or C.
  5. Restart the radar.

Troubleshooting

Radar not detected

DRS4W: confirm you are on the radar's WiFi and started Mayara with --allow-wifi.

Wired radars:

  1. Confirm the Mayara machine has a 172.31.x.x address.
  2. Confirm the Ethernet cable reaches the radar's network port.
  3. For a FAR-2xx7, confirm IMO mode is W and not A.
  4. Check the firewall — the radar uses UDP broadcast and multicast.

FAR shows an unknown model

The part code is not in the lookup table yet. The radar still works with default capabilities; report the code from the log so it can be added.

Controls stop working, or the radar flips between picture and OFF

Furuno radars keep only one control session per client IP address. A second Mayara instance on the same machine — a container using host networking next to a development instance, for example — fights the first one for that single slot. The radar serves each new login briefly, then closes it; both instances reconnect forever and neither holds the session.

Spoke data is unaffected, because it arrives by multicast, so the picture keeps painting while the controls fail. Run one Mayara instance per host when a Furuno radar is in use. Clients on other machines — TimeZero, an MFD — have their own IP and do not conflict.
